# Release notes

## v0.2.0 — correctness, readability, packaging

This release is the result of a structured audit of the package
(`OPTIMIZATION_PROGRESS.md` records the full evidence trail). Nothing in the
numerical methods was rewritten; what changed is that the code is now
*correct where it previously could not run*, *readable where the reader had to
guess*, and *installable with a dependency list that describes it*.

The patch test's L2 error has been `6.594194188924542e-8` before and after every
step below, so the numerical behaviour of the working code is unchanged.

### Breaking changes

Read this section first — five of these change the API.

| change | what to do |
|---|---|
| **Material constants are keyword arguments** (123 operators) | `prescribe!(el, :E => …)` followed by `(form => el)(k)` becomes `(form => el)(k; E = …, ν = …)` |
| **The global `op` no longer exists** | it was already deleted; 138 references to it were replaced by `ξ.<field>` reads |
| **`∫∇v∇udx` and siblings take `kᶜ`, not `k`** | the thermal conductivity collides with the stiffness-matrix argument `k`; `(form => el)(k; kᶜ = 1.0)` |
| **`getPiecewiseElements`, `getPiecewiseBoundaryElements`, `getCurvedPiecewiseElements` removed** | they called `get𝑛𝑝(::Element)`, a method that never existed, so they could not run; build piecewise elements directly instead |
| **`approximation/grkgsi.jl` removed** | it extended `AbstractReproducingKernel`, a type that was never defined |
| **`addEdgeElements` is no longer exported** | it is not defined anywhere in the package |
| **`julia = "1.9"` required** | previously `"1"` |
| **`getCurvedElements` no longer requires `cs::Function`** | `cs` must carry `𝐽`, `a₁₁`, … as *fields*; a `NamedTuple` of functions now works |

### Fixed — code that could not run

- **138 references to a deleted global `op`** across seven modules. Every one of
  those operators raised `UndefVarError` on first call.
- **`Seg3` gradients were multiplied by `J` instead of divided by it** — a factor
  of `L²` error in the derivative. Verified: `du/dx = 1.0` exactly for `u = x`
  at five sample points; the old code gave `9.0` for a segment of length 3.
- **`PiecewisePolynomial{:Constant}` read `∂𝝭∂y` from the `∂𝝭∂x` array.**
- **`SegHermite`'s gradient setter referenced an undefined variable.**
- **Statement-level dangling references** (46 sites) exposed by removing `op.`:
  `E`, `ν`, `h` were used before any binding in `hyperelasticity`,
  `error_estimates`, `plasticity`, `thin_plate`, `thin_shell`.
- **`thin_shell.jl`'s `Hₑ_ThinShell`** used `E`/`ν`/`h` before binding.
- **Nineteen operators in `phasefield.jl` and `plasticity.jl` had never been
  executed** — they were excluded from the build while dispatching on the
  deleted `Operator` struct. Bringing them back exposed: uninitialised `ε`/`v`;
  `η`, `kc`, `λ`, `μ`, `c`, `K`, `σy`, `tol` read but never declared; an
  unqualified cross-module `getσₙ` call; and three title-only docstrings that
  orphaned the real documentation.
- **`prescribe!` failed on any 2-argument value function** (`(x, y) -> …`),
  because it only tested `applicable(f, x, y, z)`. It also raised `KeyError` on
  `ξ.n₃` for 2-D boundary elements, which have no `ξ.n₃`.
- **`getCurvedElements` could never be called**: the signature required
  `cs::Function` while the body read `cs.𝐽`, `cs.a₁₁`, … as fields — no argument
  satisfies both. The `::Function` restriction is removed and the curvature-
  corrected Jacobian is now exercised by a test that asserts `Σ ξ.𝑤` scales with
  `cs.𝐽`.

### Changed — readability

- **264 operator docstrings**, up from ~22. Each states the weak form, the
  quadrature-point fields it reads (so the caller knows whether `set𝝭!`,
  `set∇𝝭!` or `set∇²𝝭!` is required), its keyword arguments, and the meaning
  where a symbol differs between modules (`α`, `k`/`kᶜ`, `c`/`c²`).
- **The Gmsh importer is rebuilt.** 1049 lines of `quote` fragments spliced by
  `@eval` into 17 near-identical functions became three files — `importmsh.jl`
  (397 lines: entity reading plus every legacy signature as a thin forwarder),
  `elements.jl` (284: `ElementSpec` and the single `getElements` with four
  dispatch points) and `coordinates.jl` (350: the `fill_*` helpers) — with no
  duplicated function body left.
- **The `data`-dictionary layout is documented** at last: the four index slots,
  what `:𝐽` means (and why 1-D elements divide by it), and the per-field
  ownership.
- **`README.md`: one line → a user guide** with a runnable patch test, a runnable
  2-D elasticity example, the data model, how to write a weak form, and how to
  add an element type.
- **`docs/src/operators.md`**: a generated index of all 264 operators — module,
  required setter, material constants, description. Regenerated by
  `scripts/build_operator_index.py`, so it cannot drift from the code.

### Added

- **`get𝑿ᵢ(centroid = entities["Ω"])`** and `GmshImport.addCentroidNodes!` — one
  extra node at the centroid of every element, appended after the mesh nodes so
  existing `𝐼` indices are untouched. Uses the **corner** nodes, so a quadratic
  element's centroid is not pulled towards its mid-side nodes.
- **Characterisation tests for the importer** (96 assertions): element count,
  `data` keys, `Σ ξ.𝑤`, centroid nodes, curved-surface scaling, and the
  invariant that all quadrature points share one `data` dictionary.
- **Shape-function consistency tests** (86 assertions) for `Seg2/3`, `Tri3/6`,
  `Quad4`, `Hex8`, `Tet4`, `Quad8`, `Tet10`, `TriBell`, `TriHermite`:
  partition of unity, nodal delta, and linear-field reproduction.
- **Package hygiene tests** using Aqua.jl: no undefined exports, no method
  ambiguities, no stale dependencies, compat bounds present, no type piracy.
- **`REPRODUCIBILITY.md`** recording the environment and the numerical values
  that must reproduce, each with the test that asserts it.

### Fixed — packaging

- `WriteVTK` removed from `[deps]`: it was declared and never imported.
- `[compat]` now covers `Gmsh`, `Printf`, `julia` and the test-only dependencies;
  it previously covered only the unused `WriteVTK`.
- Five names were `export`ed that did not exist in the module exporting them
  (`getPhysicalGroups`, `get𝑿ᵢ`, `getElements`, `getCurvedElements`,
  `addEdgeElements`). The first four are now re-exported from `GmshImport`, so
  `using ApproxOperator` really does provide them; `addEdgeElements` is removed.
- Two `push!` methods were variadic-only, making `push!(aps)` ambiguous.

### Test suite

103 → **242** assertions. The suite is now organised by what it protects:

| file | protects |
|---|---|
| `patchtest.jl` | the end-to-end pipeline |
| `importer_characterisation.jl` | the importer's output |
| `shape_function_consistency.jl` | the mathematics of every element family |
| `operators_material_parameter.jl` | material constants as keywords |
| `restored_modules.jl` | the plasticity / phase-field operators |
| `package_hygiene.jl` | packaging |

### Known limitations

- `getCurvedElements` works, but its `cs` argument convention (fields, not a
  function) is unlike anything else in the package; the docstring says so.
- `fill_jacobian!` preserves a historical quirk: the `z`-direction
  inverse-Jacobian entries are written inside an `elseif dim >= 3` branch that an
  earlier `dim >= 2` test makes unreachable, so those arrays stay empty for 3-D
  elements. Fixing it would change 3-D results, so it is documented, not changed.
- Most operator docstrings state the weak form inline (`` `∫ k ∇v·∇u dΩ` ``)
  rather than as a display block. Both carry the same content; 67 operators whose
  mathematics needed unfolding use the display form.
- `Manifest.toml` is not committed; see `REPRODUCIBILITY.md`.
